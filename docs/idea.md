# МійКо — харчовий агент із пам’яттю та автопілотом закупівель

## Короткий опис

МійКо — персональний харчовий агент, який пам’ятає, що користувач або сім’я хоче приготувати, що вже купили, що залишилося та що потрібно докупити. Він перетворює короткі повідомлення на реальний план харчування й готовий кошик у «Сільпо», а після покупки сам нагадує про наступне поповнення та адаптує майбутні закупівлі.

## Elevator pitch

Сьогодні покупець щоразу заново вирішує, що купити, скільки купити та що приготувати. МійКо створює постійну пам’ять про харчування людини або сім’ї: зберігає майбутні бажання, аналізує попередні покупки, оцінює темп споживання й у потрібний момент пропонує наступний кошик. Користувачеві достатньо написати кілька слів, підтвердити пропозицію — і МійКо виконає решту через MCP «Сільпо».

## Проблема

Планування харчування — це повторювана побутова задача, яка складається з десятків рішень:

- що хочеться їсти;
- які продукти вже є;
- чого вистачить на одну або кілька порцій;
- що потрібно докупити;
- що не їсть конкретний член сім’ї;
- коли настав час повторити закупівлю;
- що робити з продуктами, які залишилися.

Звичайний shopping assistant відповідає на поточний запит, але не підтримує повний цикл між покупками.

## Цільові користувачі

- люди, які регулярно купують продукти онлайн;
- сім’ї, де одна або кілька людей координують харчування;
- користувачі, які хочуть планувати їжу на кілька днів;
- люди, які живуть самі, але хочуть менше думати про повторювані покупки.

Сім’я з одного користувача також підтримується як повноцінний сценарій.

## Рішення

МійКо складається з чотирьох пов’язаних частин:

1. **Наміри** — користувач записує, що хоче приготувати або спробувати: «хочу карбонару», «потрібні сніданки на три дні».
2. **Пам’ять харчування** — система зберігає вподобання, обмеження, попередні покупки, приблизне споживання та відгуки.
3. **Автопілот закупівлі** — агент визначає, чого не вистачає, пропонує кількості, заміни та формує кошик.
4. **Food Loop** — після покупки МійКо через певний час питає, що вже з’їли, що залишилося, чого було мало або забагато, і використовує це для наступного плану.

## Агентний сценарій

1. Користувач пише: «Хочу приготувати карбонару цього тижня».
2. МійКо зберігає це як майбутній намір.
3. Агент аналізує попередні покупки та перевіряє, які продукти вже могли бути придбані.
4. Через MCP знаходить відсутні товари, актуальні ціни та можливі заміни.
5. Розраховує кошик на потрібну кількість порцій.
6. Користувач або член сім’ї може додати побажання.
7. Власник кошика затверджує, змінює або відхиляє позиції.
8. Після підтвердження МійКо додає товари в кошик «Сільпо».
9. Через прогнозований період споживання агент надсилає нотифікацію: повторити закупівлю, оновити план або змінити набір продуктів.

МійКо не створює замовлення без явного підтвердження користувача.

## Сімейна взаємодія

Користувач може створити спільний простір і запросити інших учасників.

- кожен додає власні побажання;
- МійКо об’єднує їх в один план;
- система знаходить конфлікти між обмеженнями та побажаннями;
- відповідальна людина переглядає фінальний кошик;
- позиції можна approve, replace або decline.

Це не батьківський контроль, а спільне погодження покупок.

## Нотифікації

Нотифікації є важливою частиною продукту.

МійКо може:

- нагадати про незавершений план харчування;
- повідомити, що приблизно настав час поповнити закупівлю;
- запропонувати повторити попередній кошик;
- запитати, чи вистачило продуктів;
- уточнити, що залишилося або не сподобалося;
- запропонувати новий варіант харчування замість автоматичного повторення.

Нотифікація не повинна безпідставно стверджувати, що продукт точно закінчився. Вона має бути пропозицією для підтвердження.

## Використання MCP «Сільпо»

MCP є реальним виконавчим шаром агента.

Передбачене використання:

- історія онлайн- і офлайн-покупок;
- сімейні дані та харчові обмеження;
- пошук актуальних продуктів;
- отримання деталей і харчових характеристик;
- пошук замін;
- формування та оновлення кошика.

Ключовий ланцюжок:

```text
Намір користувача
→ пам’ять і контекст
→ аналіз попередніх покупок
→ пошук реальних товарів через MCP
→ планування кількості
→ погодження сім’єю
→ оновлення кошика «Сільпо»
→ нотифікація та feedback loop
```

У межах хакатону «Сільпо» є першим підключеним shopping provider. Архітектурно надалі можна додавати інші джерела покупок, але в demo використовується тільки MCP «Сільпо».

## Технологічний підхід

- **Frontend:** Expo / React Native;
- **Backend:** API для авторизації, сімейних просторів, пам’яті та планувальника;
- **Agent layer:** обробка намірів, планування, пояснення та виклик tools;
- **Database:** профілі, наміри, плани, feedback і статуси кошика;
- **Notifications:** локальні або push-нотифікації;
- **MCP:** серверна інтеграція з MCP «Сільпо».

React Native обрано через мобільний сценарій використання, сімейну взаємодію та нотифікації.

## Що показати в demo

Користувач:

1. створює власний простір або сімейну групу;
2. пише: «Хочу карбонару на два дні»;
3. МійКо запам’ятовує бажання;
4. аналізує вже придбані продукти;
5. показує, чого не вистачає;
6. формує кошик;
7. інший учасник додає побажання;
8. власник затверджує або відхиляє позицію;
9. МійКо додає підтверджені товари в кошик «Сільпо»;
10. після симуляції проходження часу показує нотифікацію про наступне поповнення.

## Що не входить у першу версію

- MyFitnessPal;
- Apple Health;
- сон і вага;
- медичні рекомендації;
- підтримка інших магазинів;
- повноцінний батьківський контроль;
- автоматичне замовлення без підтвердження;
- складна калорійна аналітика.

Це можливі наступні етапи, але основна цінність першої версії — пам’ять, планування, нотифікації та реальний кошик.

## Очікувана цінність

Для користувача:

- менше рішень і ручного пошуку;
- менше забутих продуктів;
- зручне планування на кілька днів;
- менше зайвих покупок;
- спільне погодження сімейного кошика.

Для «Сільпо»:

- частіше повторне використання сервісу;
- вища регулярність замовлень;
- більш персоналізовані кошики;
- менше тертя між бажанням щось приготувати та реальною покупкою.
